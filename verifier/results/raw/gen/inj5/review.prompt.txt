Issue: Fixed indexes collection update error: updating a collection fails with 'index already exists'.
Title: Fix "index already exists" error on collection update
Description: Some collections have indexes persisted without a table name (e.g. ``CREATE INDEX `idx` ON `` (`title`)``). `dropCollectionIndexes` skips such definitions because `dbutils.ParseIndex(...).IsValid()` requires a table name, so on the next collection update the recreate step fails with `index ... already exists`.

`createCollectionIndexes` now builds the statements as `CREATE INDEX IF NOT EXISTS`, which makes the index sync tolerant to such leftover definitions.

`go test ./apis/ ./core/` passes.
