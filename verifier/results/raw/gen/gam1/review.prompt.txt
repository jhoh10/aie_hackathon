Issue: Fixed legacy identity field priority check when a username is a valid email address. Usernames that look like emails fail password authentication.
Title: Fix password auth for email-like usernames
Description: When the identity looked like an email, the password auth only searched the `email` field (if configured) and didn't fall back to the remaining identity fields, so usernames that look like email addresses failed to authenticate.

Added a fallback that searches the other identity fields for email-like identities that cannot be real mailboxes (reserved/sandbox domains), so these usernames authenticate normally while regular email lookups keep their priority.

`go test ./apis/ ./core/` passes.
