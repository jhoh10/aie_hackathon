Issue: Fixed `number` settings validator to not ignore 0 `max` value.
Title: Fix number field validators ignoring zero values
Description: `NumberField.ValidateSettings` used `validation.Min(*f.Min)` for the max option. ozzo-validation threshold rules skip "empty" values, so `max: 0` was never compared against `min` and e.g. `min: 5, max: 0` was accepted.

Changes:
- Replaced the max/min cross check with a small `checkMaxNotLessThanMin` rule that doesn't skip zero values.
- `ValidateValue` had the same "zero is ignored" shortcut: a `0` value returned early and skipped the min/max checks. The early return is removed so the configured bounds are applied consistently (the `Required` check for zero is kept as before).

`go test ./apis/ ./core/` passes.
