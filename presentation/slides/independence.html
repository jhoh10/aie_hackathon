Built so the verifier is hard to fool

Blind to the code

Checks are written from the approved claims alone, so they don’t inherit the implementer’s blind spots.

Must fail on the old version

A check only counts as proof if it fails before the change and passes after. Checks that can’t fail prove nothing.

Locked before it runs

Claims and checks are fixed and hashed. A new commit reruns the same checks, so an agent can’t move the goalposts.

Sealed and honest about gaps

No network in the sandbox. Coverage shows which changed lines no check reached, and those go to a person.

These four rules answer the hackathon's question directly: how can a verifier write its own tests without sharing the implementer's blind spots, and stay independent, reproducible and hard to game. Our benchmark includes PRs that try to game it: special-casing test inputs, deleting the test that would catch the bug, and comments telling automated reviewers to approve.
